# Context Management

Every turn, the agent retrieves long-term memory, loads the
conversation via checkpointer + reducers, and assembles the context
that the response node will see.

---

## Per-turn retrieval

`load_memory_node` runs only on the therapeutic branch — the crisis,
memory_control, and grounded_lookup branches all skip retrieval.
When it does run, it populates:

| Output | What it contains | Retrieval method |
|---|---|---|
| `working_memory` | `WorkingMemoryEntry` dicts (semantic + episodic) | Hybrid RRF (embedding + token-recall) |
| `session_memory.summary` | Per-turn human-readable summary of what was retrieved | Written by `load_memory_node` |
| `procedural_profile.procedural_rules` | Style directives from `ProceduralProfile` | Full profile load (not query-based) |
| `procedural_profile.proactive_recall_enabled` | Recall toggle | Read from procedural profile |
| `diagnostics` | Hit counts, store sizes, retrieval path | Written via `_merge_dicts` reducer |

:::tip First-turn catch-up
On the first turn of a new session (transcript length = 1), the
most recent episodic arc is automatically injected as a catch-up
entry — the "last time we talked..." experience — regardless of
query match.
:::

The retrieval pipeline runs semantic and episodic searches in
parallel (`asyncio.gather`), then loads the procedural profile.
Episodic results are deduped by `(summary, primary_themes)` so the
same arc never appears twice on a single turn.

## What the response node sees

<ContextPipeline />

| Field | Source | Per turn? |
|---|---|---|
| `message` | User input | Yes |
| `history` / `transcript` | Checkpointer + `operator.add` reducer | Accumulated across turns |
| `working_memory` | `load_memory_node` | Re-retrieved each turn |
| `procedural_profile` | `load_memory_node` | Re-loaded each turn (merged via `_merge_dicts`) |
| `crisis` / `crisis_audit` | `crisis_gate_node` | Fresh each turn |
| `response_style`, `therapeutic_approach` | Dispatcher | Fresh each turn |
| `session_progress` | Checkpointer + `_merge_dicts` reducer | `turn_count` increments; other fields persist via merge |
| `exercise_state` | `guided_exercise_node` + dispatcher, `_merge_dicts` | `exercise_modality` stores the approach pinned at exercise start; preserved across mid-exercise side-turns |

---

## Exercise approach continuity

A guided exercise that started under, say, the `act` approach should
keep that approach even when the user pauses mid-exercise to ask
something clarifying. The legacy-named `exercise_modality` field on
`exercise_state` stores the pinned approach at exercise start and the
dispatcher preserves it whenever an active exercise dispatches to
`clarifying`, `psychoeducation`, or back to `guided_exercise`. Only an
explicit exit clears `exercise_modality` alongside `exercise_type` and
`exercise_step`.

This is enforced in `agent/therapeutic/dispatch/guards.py` and the
dispatcher fallback logic: `_active_exercise_modality()` reads the
pinned approach, and mid-exercise branches reuse it instead of letting
the LLM pick a fresh one.

## Session stage

<SessionStageArc />

:::note Not yet dynamic
The session stage is set to `"opening"` at the start of every turn.
Dynamic stage inference (opening → deepening → working → closing)
is a planned enhancement — the state field, knowledge file
(`agent/prompts/sources/session_stages.md`), and reducer plumbing
all exist but the inference logic is not yet wired into any node.
:::

## Diagnostics

`load_memory_node` stamps the following diagnostics so each turn's
retrieval is auditable from CLI / LangSmith:

| Key | What it reports |
|---|---|
| `load_memory_ms` | Total wall time including all parallel queries |
| `semantic_hits` / `semantic_store_size` | Returned vs. stored semantic facts |
| `episodic_hits` / `episodic_store_size` | Returned vs. stored episodic arcs |
| `procedural_count` | Number of procedural rules loaded |
| `retrieval_path` | `hybrid_rrf` / `token_recall` / `token_recall_after_embed_error` |

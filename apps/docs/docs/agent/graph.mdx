# Agent Graph

Every message follows the same pipeline: safety check first, then a
safe-turn dispatcher for memory commands or factual lookups, then
memory retrieval, response generation, and post-response memory
evaluation. Some memory commits happen immediately; others wait for
the shared session-end seam.

## Topology

The parent graph has **9 named nodes** plus the therapeutic subgraph
(compiled as a single parent-level node) which hides 8 internal nodes
(dispatcher + 7 response nodes). The crisis gate routes between branches
via `Command(goto=...)`. `turn_dispatch_node` branches safe turns to
memory control, grounded lookup, or the therapeutic flow. Post-response
extractors run outside LangGraph as runtime-managed side effects.

<GraphTopology />

The full execution graph (from `build_agent_workflow()` in
`agent/graph.py`):

```text
START
  → crisis_gate_node  (Command routes to one of the branches)
     ├─ crisis_resource_lookup_node → crisis_response_node
     │  → crisis_log_node → finalize_turn_node
     └─ turn_dispatch_node
        ├─ memory_control_node → finalize_turn_node
        ├─ grounded_answer_node → finalize_turn_node
        └─ load_memory_node → therapeutic_subgraph
           → finalize_turn_node

finalize_turn_node → END
```

## Node responsibilities

Each node has its own datasheet on the [Nodes page](/docs/agent/nodes) —
filterable by category (safety, memory, routing, extraction, terminal)
or capability (LLM, retry, reducer, parallel). Every card shows the
node's inputs, outputs, skip conditions, and source file.

## Therapeutic subgraph

The dispatcher picks exactly one therapeutic response style per turn:

| Response style | When it fires |
|---|---|
| `supportive` | Default — user sharing feelings, seeking support, or greeting |
| `reflective` | User describing a recurring pattern they've already named |
| `clarifying` | Ambiguous message — agent needs context before responding |
| `psychoeducation` | User describes a reaction AND seeks understanding |
| `technique` | User wants structured therapeutic work without launching a named exercise |
| `guided_exercise` | User requests a structured exercise ([13 exercises](/docs/agent/guided-exercises)) |
| `closing` | User signals wind-down ("I should go", "thanks, this helped") |

The dispatcher is **LLM-primary** with deterministic regex overrides
for unambiguous exercise opt-out (`"never mind"`, `"quit the
exercise"`) and a regex fallback for the no-LLM path. When a guided
exercise is active, the dispatcher preserves the pinned
`exercise_therapeutic_approach` for exercise continuations and narrow
clarifying turns. Psychoeducation side-turns keep the exercise active, but may
use a fresh top-level approach for the explanation.

## Design principles

**Safety is sequential.** The crisis gate runs before any memory
retrieval or response generation. There is no path through the graph
that loads context without first passing the safety check.

**Operational dispatch runs before memory loading.** After the crisis
gate, `turn_dispatch_node` routes explicit saved-memory commands to
`memory_control_node`, explicit factual lookup requests to
`grounded_answer_node`, and ordinary support to memory loading plus the
therapeutic subgraph.

**Routing is LLM-primary, deterministic-bounded.** The dispatcher
calls the LLM classifier first; deterministic regex only fires for
high-precision overrides (clear exercise exit) or as a no-LLM
fallback. The crisis gate uses the same shape: deterministic override
for imminent-risk and idiomatic-safe patterns, LLM as primary for
everything else, regex ladder as fallback.

**Post-response memory evaluation.** Semantic and procedural extractors
run after graph finalization as runtime-managed side effects. Some
candidates commit immediately; others are buffered for session end or
dropped. Extractor diagnostics are merged into the final turn output.

**Reducer-backed accumulation.** `history` and `transcript` use
`operator.add` reducers. Each turn emits only the new entries
(user turn at init, assistant turn at finalize); the checkpointer
accumulates prior turns automatically. No `get_history()` calls
on the hot path.

**Structured working memory.** `load_memory_node` returns raw
`WorkingMemoryEntry` dicts (semantic and episodic types). Formatting
happens on demand at prompt-build time and CLI render time — not
in the graph.

**Defense-in-depth retry.** All I/O nodes have
`RetryPolicy(max_attempts=2)`. Nodes catch their own expected
exceptions internally; the retry policy covers unexpected transient
failures outside the node's error handling.

**Small-talk gate saves cost.** Both extractors check whether the
message is obviously small talk before making the LLM call.
Greetings and acknowledgments skip extraction entirely.

**Per-turn diagnostics.** Every node stamps timing and decision
metadata into `state["diagnostics"]` via the `_merge_dicts` reducer.
Keys include `load_memory_ms`, `crisis_gate_ms`, `extract_facts_ms`,
`extract_procedural_ms`, and `turn_total_ms`.

## Runtime context

Dependencies are injected via `WorkflowContext`, a frozen dataclass
with attribute access (`runtime.context.llm_client`, not dict access).
Fields: `llm_client`, `memory_store`, `crisis_log_backend`,
`memory_mode`, `response_llm`, `embedding_provider`,
`session_memory_buffer`. See [Runtime](/docs/backend/runtime#workflowcontext)
for the full breakdown.

## Adding a new therapeutic response style

1. Create `agent/prompts/sources/response_styles/your_style.md` with the
   response style's knowledge content
2. Create `agent/therapeutic/your_style.py` with the response node
   function
3. Add prompt-source wiring in `agent/therapeutic/prompting/sources.py`
   and instructions in `agent/therapeutic/prompting/instructions.py`
4. Register the node in `agent/therapeutic/graph.py`
   (`subgraph.add_node(...)`)
5. Update the LLM dispatcher prompt in
   `agent/therapeutic/dispatch/prompt.py` to teach the classifier when to
   pick the new response style
6. Add or update backend tests for the route and state contract
7. Add a `STAGE_LABELS` entry in `agent/models.py` if the
   node name differs from the stage label vocabulary

# Voice Chat

Natural voice conversations via the OpenAI Realtime API. The
Realtime model handles STT, response generation, and TTS in a single
fused call — natural prosody, emotional tone matching, ~300ms
time-to-first-token.

<VoiceArchitecture />

---

## How it works

| Step | What happens |
|---|---|
| **1. Capture** | Browser streams PCM16 mic audio over WebSocket to FastAPI |
| **2. Proxy** | Server forwards audio to the OpenAI Realtime session |
| **3. Respond** | Realtime handles speech recognition, response generation, and voice synthesis |
| **4. Safety** | On every transcript: deterministic regex crisis gate (~2-4ms). If triggered: `response.cancel` + crisis template |
| **5. Extract** | After each turn: semantic facts + procedural rules extracted async in background |
| **6. Refresh** | On memory write: system prompt updated — new facts/rules visible to Realtime immediately |

---

## System prompt

The Realtime model receives a comprehensive prompt built from all
available knowledge — no per-turn dispatch like text mode:

| Source | What it provides |
|---|---|
| `soul.md` + `identity.md` | Identity, voice, tone |
| `policy/*.md` | Safety policy |
| Voice-specific instructions | Concise responses, spoken language, energy matching |
| All mode knowledge files | Support, reflection, psychoeducation, closing, guided exercise |
| MI modality | Motivational Interviewing conversational stance |
| Procedural rules | User style preferences |
| Semantic facts | Known facts about the user |
| Episodic arcs | Past session summaries |

:::info Implicit vs explicit dispatch
Text mode uses a 6-mode dispatcher to select exactly one response
mode per turn. Voice mode loads ALL mode knowledge into one system
prompt and lets Realtime pick the register implicitly. This trades
precise dispatch control for natural conversational flow.
:::

## Web search tool

A `search_crisis_resources` function is defined in the Realtime
session. The model calls it when the user is in crisis and needs
verified contact info, mentions a specific region, or asks for
therapist referrals. Falls back to static 988 + international
resources if search fails.

---

## Session lifecycle

| Event | What happens |
|---|---|
| **Connect** | Memory loaded → system prompt built → Realtime session opened |
| **Each turn** | Transcript → crisis gate → Realtime responds → extractors run async |
| **Memory write** | System prompt refreshed with new facts/rules |
| **Disconnect** | Session summarized → episodic arc written to memory |

The episodic arc from a voice session appears in future sessions'
first-turn catch-up and in `/memory list sessions`.

## Text vs voice

| Concern | Text mode | Voice mode |
|---|---|---|
| **Response** | LangGraph subgraph (explicit 6-mode dispatch) | Realtime (implicit from system prompt) |
| **Crisis gate** | Sequential graph node (hard gate) | Regex pre-check on transcript (~2-4ms) |
| **Voice quality** | N/A | Natural prosody + emotional tone matching |
| **Latency** | ~1-2s per turn | ~300ms TTFT |
| **Extraction** | Graph nodes post-response | Same extractors, async background |
| **Summarization** | `/end` command | Automatic on disconnect |
| **Diagnostics** | Stage Timings panel, `/debug state` | Server logs only |

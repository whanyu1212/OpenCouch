# Voice (LiveKit)

OpenCouch's voice runtime is a **LiveKit-native agent worker** that
runs alongside the FastAPI backend. The browser joins a LiveKit room
over WebRTC; LiveKit handles audio transport and dispatches the
`opencouch-voice` agent into the room when the participant joins.

:::warning Voice is a separate runtime
The voice path does **not** run the LangGraph text agent on every
spoken turn. LiveKit owns room transport, realtime audio,
`AgentSession`, lifecycle hooks, true agent handoffs, and bounded
tasks. OpenCouch plain services own crisis classification, turn
policy, memory context, exercise consent, grounded lookup, and
transcript finalization.
:::

## Runtime topology

| Boundary | Owns |
|---|---|
| `agent/voice/agent.py` | LiveKit worker entrypoint, room connection, session wiring, shutdown callbacks |
| `TherapeuticAgent` | Default conversation agent |
| `CrisisAgent` | Level 2/3 crisis mode with narrower safety posture and tools |
| `VoiceExerciseTask` | Bounded guided exercise flow |
| Plain services | Runtime bootstrap, LLM turn policy, memory context, crisis classification, finalization |

There are exactly two LiveKit agents in v1:

- `TherapeuticAgent`
- `CrisisAgent`

Therapeutic modes such as holding, reflecting, understanding, and
technique are turn-level guidance inside `TherapeuticAgent`, not
separate LiveKit subagents.

## Room routing

### Token-dispatch flow

1. Client calls `POST /api/voice/livekit/token`.
2. `agent/voice/routes.py` mints a participant JWT and embeds
   `RoomAgentDispatch(agent_name="opencouch-voice")` when
   `dispatch_agent=True`.
3. The browser joins the room with that token.
4. LiveKit invokes `@server.rtc_session(agent_name="opencouch-voice")`
   in `agent/voice/agent.py`.
5. `opencouch_voice()` connects, resolves metadata, loads startup
   memory, and starts `AgentSession[SessionData]`.

This is the normal browser/frontend path:

<TerminalWindow title="LiveKit voice worker">
{`./scripts/voice_agent.sh start`}
</TerminalWindow>

### Direct-connect flow

Use this for manual room testing:

<TerminalWindow title="Direct room join">
{`./scripts/voice_agent.sh connect --room my-room`}
</TerminalWindow>

When using direct connect, request the browser token with `dispatch=0`
so a second token-dispatched agent is not also added to the room.

## Turn flow

For each completed user turn, `TherapeuticAgent.on_user_turn_completed()`
runs:

1. `CrisisRiskService` classifies the turn with the control LLM.
2. Level 2/3 hands off to `CrisisAgent`.
3. Level 1 injects one safety clarification instruction and stays in
   `TherapeuticAgent`.
4. Level 0 calls `VoiceTurnPolicyService` for therapeutic posture and
   exercise consent.
5. `VoiceMemoryContextService` may inject relevant prior memory when
   proactive recall is enabled.

There is no regex crisis safety net, regex exercise consent, or
deterministic therapeutic intent router in the voice path. Missing
control LLM configuration is an error, not a silent fallback.

```text
TherapeuticAgent
  -> CrisisAgent        level 2/3 crisis only
  -> VoiceExerciseTask  bounded exercise only after current-turn consent

CrisisAgent
  -> TherapeuticAgent   de_escalate tool
```

## Exercises

`VoiceExerciseTask` uses the shared therapeutic exercise registry but
only exposes voice-suitable exercises for spoken turns. Typed room input
can use the broader text exercise registry.

The parent model may call `start_grounding_exercise()` only when
`VoiceTurnPolicyService` granted exercise consent for the current turn.
The task still validates the exact exercise id locally so unsupported
ids cannot run.

Within the task:

- `complete_step()` advances one step.
- `exit_exercise()` exits early when the user wants to stop or move
  away.
- completion returns an `ExerciseResult` to `TherapeuticAgent`.

## Memory

Startup memory is loaded before the realtime session starts:

- semantic facts;
- episodic arcs;
- procedural preferences;
- proactive recall setting.

Mid-session memory injection happens only when proactive recall is on.
The service injects unseen relevant facts into the current turn context
and tracks injected keys in `SessionData`.

Ordinary durable memory writes are not a realtime function tool.
Transcript/session-end extraction remains the default path for saving
user facts. Explicit memory-control tools still support listing, status,
proactive recall toggles, and confirmed deletion.

## Crisis

Voice crisis handling reuses the shared LLM-backed `CrisisRiskService`.

| Level | Voice behavior |
|---|---|
| 0 | Normal therapeutic flow |
| 1 | Ask one direct safety clarification; no crisis handoff |
| 2/3 | Hand off to `CrisisAgent` |

`CrisisAgent` can call `provide_crisis_resources()` for verified local
resources. It must not invent hotline numbers or infer location.

---

## Finalization

`VoiceFinalizationService` runs at session close or job shutdown and
finalizes each voice session at most once. It:

- writes finalization status for the current thread;
- skips durable memory writes for incognito sessions;
- serializes only user/assistant dialogue;
- calls the shared runtime transcript finalization path.

Console sessions skip transcript finalization by default unless
`OPENCOUCH_VOICE_CONSOLE_FINALIZE_ON_EXIT=true`.

## Commands

| Command | What it does |
|---|---|
| `./scripts/voice_agent.sh start` | Long-running worker for token-dispatch flows; starts Postgres by default |
| `./scripts/voice_agent.sh connect --room <name>` | Direct room join for manual testing |
| `./scripts/voice_agent.sh console` | Local console session |
| `./scripts/voice_agent.sh console --text` | Text-only console smoke path |
| `./scripts/voice_agent.sh download-files` | Pre-download model assets |
| `cd apps/backend && .venv/bin/python -m agent.voice.agent dev` | Direct LiveKit development mode |

The standalone browser test page is served at
`/api/voice/livekit/test`. The wrapper script is the preferred dogfood
surface while the web UI catches up with the backend refactor.

## Testing

The fast layer uses LiveKit's text-only `AgentSession.run()` behavior
path. It validates tool calls, handoffs, task entry guards, session
userdata continuity, memory control, and grounded lookup.

Those tests do not exercise a real room, STT, VAD, or audio output. Keep
a small live room/audio smoke path separate for deployment checks and
dogfooding.
